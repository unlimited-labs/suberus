Suberus has five roles. Every user has one, and the role decides what they can see
and do. Roles are assigned and changed in
**[Managing the conference › Users](/managing/users/)**.

| Role | Who they are | What they can do |
|---|---|---|
| **Author** | Anyone submitting work. | Create submissions, view and revise their own, withdraw them. |
| **Reviewer** | People who review submissions. | Everything an author can, plus: be assigned reviews, see assigned submissions, and submit reviews. |
| **Editor** | Handling editors / programme committee. | See **all** submissions and reviews (including private notes), assign reviewers, make decisions, and change user roles — **except** granting/removing Administrator. |
| **Admin** | System administrators. | Everything an editor can, plus full configuration, granting Administrator, and editing/deleting user accounts. |
| **Exhibitor** | Company representatives. | Complete their company application (with an optional company presentation) in their own panel. They cannot create regular submissions or review. |

<Aside type="note">
Everyone — except Exhibitors — can create submissions and view their own.
Editors and Admins can also be **assigned as reviewers**, just like a Reviewer.
</Aside>

<Aside type="note" title="The Exhibitor role is special">
It is granted automatically when someone picks the **Exhibitor** account type on
the registration form (shown only when exhibitors are enabled in the **Exhibitors**
section of **[Conference](/configuration/conference/)**) and **cannot be assigned
or changed manually** — the role change actions skip exhibitor accounts. Their
applications are decided on the **[Exhibitors](/managing/exhibitors/)** screen.
</Aside>

## Permission matrix

| Action | Author | Reviewer | Editor | Admin |
|---|:---:|:---:|:---:|:---:|
| Create submission | ✅ | ✅ | ✅ | ✅ |
| View own submissions | ✅ | ✅ | ✅ | ✅ |
| Be assigned as reviewer | ❌ | ✅ | ✅ | ✅ |
| View assigned submissions | ❌ | ✅ | ✅ | ✅ |
| Submit a review | ❌ | ✅ | ✅ | ✅ |
| View **all** submissions | ❌ | ❌ | ✅ | ✅ |
| Assign reviewers | ❌ | ❌ | ✅ | ✅ |
| View all reviews & private notes | ❌ | ❌ | ✅ | ✅ |
| Make editor decisions | ❌ | ❌ | ✅ | ✅ |
| Change user roles (Author/Reviewer/Editor) | ❌ | ❌ | ✅ | ✅ |
| Grant or remove **Administrator** | ❌ | ❌ | ❌ | ✅ |
| Change one's **own** role | ❌ | ❌ | ❌ | ❌ |
| Edit user profiles / delete users | ❌ | ❌ | ❌ | ✅ |
| Configure the system | ❌ | ❌ | ❌ | ✅ |

<Aside type="note">
Roles are changed in **[Managing the conference › Users](/managing/users/)** — open
a user and use **Change Role**, or select several users and use the **Change role**
bulk action. Editors do not see the **Administrator** option and cannot change an
existing administrator's role; nobody can change their own role.
</Aside>

## Who sees whose name (review mode)

The **review mode** set per submission type controls identity visibility. Editors
and Admins always see every identity, regardless of mode.

| | Open | Single-blind | Double-blind |
|---|:---:|:---:|:---:|
| Author sees reviewer's identity | ✅ | ❌ | ❌ |
| Reviewer sees author's identity | ✅ | ✅ | ❌ |
| Editor / Admin see all identities | ✅ | ✅ | ✅ |

<Aside type="tip">
Set the review mode per type on **[Submission Types](/configuration/submission-types/)**.
*Single-blind* (authors don't see reviewers) is the most common for academic events.
</Aside>
