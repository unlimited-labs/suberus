# Abstract templates

One-page extended abstract for conference submission, in three formats. Each
format has a blank template and a filled example with identical layout.

| Format | Dir | Build |
|--------|-----|-------|
| Word | `docx/` | `py template/build_template.py` (regenerates both `.docx`) |
| LaTeX | `tex/` | `latexmk -pdf abstract.tex` (needs `biber`) |
| Typst | `typst/` | `typst compile abstract.typ` (fetches `cetz-plot` once) |

Files per format: `abstract.*` (blank, grey hints) and `abstract-example.*`
(filled). `tex/` and `typst/` share a `confabs` template and a BibLaTeX
`references.bib`; `docx/` is generated by `build_template.py`.

## Layout (all formats)

- **Title** — bold, centred, ≤ 2 lines.
- **Authors** — superscript markers link to affiliations; `*` = presenting.
- **Affiliations** — italic, each prefixed by its marker.
- **E-mails** — one line, author order.
- **Keywords** — 3–6, comma-separated.
- **Body** — continuous prose, no section headings. Table caption above, figure
  caption below; references numbered `[1]`, cited in order of appearance.
- A4, 2.5 cm margins, Times, two pages max.

## Edit

- **Word** — type into the `.docx`.
- **LaTeX** — `\title/\author/\affiliation/\email/\keywords` in the preamble.
- **Typst** — arguments of `#show: abstract-doc.with(...)`.

## Notes

- `docx/` round-trips through Suberus's DOCX extractor: title, authors,
  affiliations and keywords are auto-filled on upload. `verify_roundtrip.py`
  checks it — and, when `pdf-api` is reachable and an example PDF is built,
  also checks that the PDF header (docling markdown the LLM reads) carries the
  title, author surnames, e-mails and keywords.
- PDFs are build artifacts (git-ignored in `tex/` and `typst/`).
